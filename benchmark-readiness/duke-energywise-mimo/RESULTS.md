# Results and scoring contract

The blank `templates/` remain for a future real pilot; no real result is filled. The `run/` files are software/fixture evidence only. No reported zero error count from deterministic fixtures is a claim of zero real-world errors.

| Outcome | Required definition |
|---|---|
| Documentary accuracy | Correct source-faithful, correctly scoped/qualified assertions / correct + incorrect checkable assertions. Unverifiable assertions reported separately. |
| Wrong-business / wrong-suite | Separate accepted-association error counts and case IDs; source matches remain candidates until explicit review. Critical errors cannot be averaged away. |
| Decision-authority accuracy | Independently confirmed correct authority facts / confirmed correct + confirmed incorrect; report unverifiable and all five authority concepts separately. A faithfully quoted website owner is not verified utility-account authority. |
| Useful verification steps | Reviewer/rep-rated specific, justified next steps / completed assisted cases reviewed. Structural presence of a question in synthetic output is not measured usefulness. |
| Source usefulness | Score 0/1/2 for no useful evidence / relevant corroboration or uncertainty / unique material fact or contradiction; report access failures and duplicate source families. |
| Prioritization changes | Pre-brief baseline, post-brief judgment, change direction and evidence-supported rationale. No change can be useful; no CRM/enrollment or route outcome is inferred. |
| End-to-end research time | Paired manual versus assisted elapsed times including preparation, waits, verification/correction and brief completion. Exclude only logged external pauses; report timeouts, missing pairs and capped sensitivity. Software replay times are never human research measurements. |

Unknowns and supported hypotheses remain visible, but are not correct factual assertions in accuracy denominators. Source documentary accuracy and actual current-fact accuracy are distinct. No numeric confidence probability or eligibility score is emitted.

`tools/score.py` accepts marked synthetic arithmetic inputs only in this readiness package. It tests denominator handling, independent authority accuracy, critical-error override, source ratings, priority-rationale counts and paired positive-time calculations. Its invented 100/75-second arithmetic example tests a 25% formula; **those are not measured manual/assisted times**. Actual software phase durations live only in `software-trace.json`, labeled and excluded from that calculation.

Human research, real source inspection, independent human review, rep usefulness/priority ratings and time saved are not executed here. They remain null in the readiness summary. A real pilot's conclusion must be based on those actual observations, not fixture-test counts.
